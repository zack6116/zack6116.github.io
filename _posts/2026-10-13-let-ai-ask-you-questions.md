大家好，我是Zack。

先说一个场景：你听人说 AI 能做小工具，兴冲冲打开对话框，想让它给你做一个。光标闪了半小时，你一个字没打出来。

不是不会打字，是不知道怎么说需求。「帮我做个记账的」——太模糊。「我要一个能记录每天花销、按月汇总、最好有图表的网页」——写到这里你自己都乱了，到底先说功能还是先说界面？

我带过不少刚开始用 AI 的朋友，一半以上卡在这一步，然后得出结论「AI 不好用」。其实不是 AI 的锅，是方法反了。

## 我原来的做法：憋一段，赌一把

我最早也这么干：自己憋一段描述，越长越好，发出去，祈祷它懂。

结果基本是俩：

一种是它自顾自开干，做出来一个四不像。你要的记账它给你做了个日历，你说「不对」，它改，改出来又不对，来回八到十轮，最后你比它还累。

另一种更气人：它开始反问你，但问的全是「您希望采用哪种技术架构」「数据持久化方案偏好哪种」，问完你还是不会答。

憋需求这件事，我见过最狠的耗了半小时以上——就坐在对话框前面，删了写、写了删。半小时过去，AI 一个字没干活，全耗在等你开口。

## 换个方向：别你描述，让它问

后来我用了一个笨办法，一次就把这事解决了。原话就一句：

```
我不知道怎么描述需求，你来问我，
问完再动手。
```

就这么简单。它的思路会立刻从「猜你要什么」切换成「查清你要什么」。

今天我在 X 上也发了这条，实际问出来的问题一般是这五个：

```
1. 给谁用的？（自己用还是给别人用）
2. 要哪些功能？（最要紧的一两个就行）
3. 数据放哪？（记在本地还是要保存到网上）
4. 长什么样？（有没有见过的软件可以照着说）
5. 先做哪个？（第一版先实现什么）
```

注意这几个问题的妙处：没有一个需要你懂术语。它不问「架构」，问「数据放哪」；不问「交互设计」，问「长什么样，有没有照着说的」。

你用大白话逐条答就行：

```
1. 就我自己用
2. 能记一笔花销，月底能看总共花了多少
3. 数据就在我电脑上存着就行，别整登录
4. 像手机自带的备忘录那样简单
5. 先能记账，图表以后再说
```

五条答完，两三分钟。它这时候对你的需求已经比你憋半小时描述得还清楚。

## 再加一道保险：让它复述

答完别急着让它开干。补一句：

```
把你理解的需求整理成一段话给我看，
我确认了你再动手。
```

它会把刚才的问答收拢成一段「我理解你要做的是……」。这一步专治理解偏差——你觉得说清楚了，它听成了别的，白纸黑字对一遍，三秒钟揪出来。

确认没错，再让它写。这一套下来，我实测返工轮次能从八到十轮压到两三轮。

## 进阶：把问答存成模板

这招用两次之后，你会发现它每次问的问题都差不多。那更好办——把问出来的清单直接存成一个需求模板，下次做新东西，跳过提问环节，自己填空：

```
【给谁用】：
【要什么功能】：
【数据放哪】：
【长什么样】：
【第一版先做什么】：
```

填完贴给 AI，比它问你还快。我现在自己开新项目就用这个模板，五个空格填完，一分钟的活。

## 前后对比

| | 原来的做法 | 换成「它问」之后 |
|---|---|---|
| 开工前耗时 | 憋半小时起步，还未必说清 | 问答两三分钟 |
| 返工轮次 | 八到十轮来回改 | 两三轮 |
| 心理状态 | 越写越慌，怀疑自己 | 照着问题答，有底 |

省的不是那半小时本身，是半小时憋出来的那段话还说不清楚这件事。

## 两个通用原则

第一，需求说不清不是你的问题，是「单向描述」这个方式的问题。描述是你在猜它想听什么，提问是它来对齐你的真实想法。凡是「我要个东西但说不上来」的场景，都可以把「我描述」换成「它提问」——让 AI 帮你写周报总结、帮你写文案、帮你规划旅行，开头都可以用这一句。

第二，AI 反问你的那几个问题，本身就是最好的需求清单。你答的过程就是把脑子里的模糊想法落成字的过程。所以别嫌它问得多，问得越具体，后面返工越少。

## 说点局限

这招也不是万能的。它反问的方向受它自己的经验影响，有时候会把你往 Web 网页那条路上带，而你其实想要个手机 App——发现方向不对就直说，「我想要的不是网页，是手机上用的」，它会重新问。

另外，问题越大这招越不够用。做个小工具、写篇文章的提效明显；要是整个产品的需求，还是得你自己先把「给谁用、解决什么问题」想清楚，AI 只能帮你把想清楚的东西问出来，替你想不了。
